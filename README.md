# TrackerWatch Android

A native Android **DNS tracker monitor** inspired by the Reddit screenshot supplied by the project owner. This is an independent implementation, not the original author's app or source code.

## Download and install

1. Open the repository's **Actions → Build Android APK**.
2. Select a successful run for the latest commit.
3. Download **TrackerWatch-Android-APK** under Artifacts (GitHub login required).
4. Extract the ZIP in Samsung **My Files**. Install **TrackerWatch-0.1.0-debug.apk**, not the ZIP.
5. If Android asks, allow installation from the file manager for this install.
6. Open TrackerWatch → Start monitoring → read the resolver disclosure → accept Android's VPN prompt.

Requires Android 8.0 or later (API 26). Package: `in.trackerwatch.app`. It is a debug APK, not a Play Store release. Build reports, signature details, APK metadata and SHA-256 are generated by CI. CI compilation is not proof of operation on a physical phone.

On Samsung, if monitoring stops when the app goes into the background, check Settings → Apps → TrackerWatch → Battery. Device testing is required before changing battery settings or relying on long-duration measurements. The app does not auto-start on reboot.

## Implemented in 0.1.0

- User-started foreground local VPN with persistent notification and stop control.
- Ordinary IPv4 UDP DNS parsing, forwarding to Cloudflare `1.1.1.1:53`, and local NXDOMAIN replies for blocked domains.
- Last-24-hour request count, tracker-list match count, label count, blocked count and locked-device share.
- Rolling hourly chart and recent 100 observations.
- 25 explicitly bundled starter domain rules with company/product labels.
- Blocking off by default; custom domain rules and an allowlist. Exact domain and subdomain matching.
- App-private SQLite history capped at seven days and 20,000 entries.
- CSV export through Android's document picker and local history deletion.
- Informational checks: screen-lock configuration, USB debugging setting, Private DNS state and security patch date.
- JVM tests for malformed packets, response integrity, domain boundaries and allowlist precedence.
- GitHub Actions runs unit tests, Android lint, builds the debug APK, verifies its signature and uploads artifacts.

## Scope and privacy

**DNS queries are not tracking connections or proof of data exfiltration.** Repeated lookups count separately. “While locked” uses Android's `KeyguardManager.isDeviceLocked()` at receipt; it is not simply screen-off detection. A starter-list match indicates a domain associated with advertising, analytics or reporting, not malware.

The VPN routes only `203.0.113.53/32`, a synthetic DNS endpoint. It is not a full-tunnel VPN and does not anonymize or encrypt web traffic. Real internet traffic follows normal routes. Only one Android VPN can be active at a time.

Allowed DNS requests are sent to Cloudflare in plaintext UDP. Cloudflare and the network can see them. Blocked requests are answered locally. There is no account, analytics SDK or remote upload of stored logs. Android backup is disabled. Exported CSV files leave the app sandbox only when you choose a destination.

**Not implemented:** per-app DNS attribution; embedded SDK/APK scanning; stalkerware detection; certificate inspection; alerts for phishing domains; comprehensive blocklist updates; DNS-over-TCP; full IPv6 packet interception. Encrypted DNS, private/custom resolvers, cached DNS, direct-IP connections and traffic bypassing the VPN can be missed. Truncated DNS responses that require TCP may fail. This is a functional first-version implementation with these limitations, not feature parity with the screenshot.

To test ordinary DNS, temporarily turn off Android Private DNS and the browser's Secure DNS yourself, if you choose. Record and restore your previous settings after testing. **Do not enable “Block connections without VPN”**, because the VPN routes only DNS. Some networks block external port 53 and will show resolver errors.

The 25 starter rules are a small hand-maintained list, not an imported comprehensive database. Broad domain rules can break useful features. The allowlist overrides blocking. Blocking does not terminate existing connections or remove cached addresses; only new DNS requests are affected.

## Build

Toolchain: JDK 17, Gradle 8.11.1, Android Gradle Plugin 8.9.2, SDK platform 35, Build Tools 35.0.0.

With Gradle 8.11.1 installed and `ANDROID_HOME` set:

```sh
sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
gradle --no-daemon :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
```

Output: `app/build/outputs/apk/debug/app-debug.apk`. CI installs the same versions. There is no Gradle wrapper binary in this initial source tree. Android Studio users can use the stated local Gradle version or generate a wrapper with `gradle wrapper --gradle-version 8.11.1`.

CI caches its debug signing key to permit updates when the cache survives. If Android reports a signature conflict after a later build, preserve any needed CSV first, then uninstall the previous debug build and install the new one. Uninstalling deletes private history. A production signing key is not configured.

## Device acceptance checklist (not yet verified)

- Install on Samsung S23 Ultra and open all four tabs.
- Deny the VPN prompt: monitoring stays off; allow it: notification appears.
- With standard DNS enabled, open an uncached website: it loads and a DNS observation appears.
- Add a test domain to custom rules, enable blocking, and query it without a cached address: verify NXDOMAIN and a blocked observation.
- Allow that domain: a fresh query resolves.
- Generate DNS activity while Android reports the phone locked, then verify the locked count.
- Switch Wi-Fi/mobile data; test offline and resume. Resolver failures should appear explicitly.
- Stop from the notification and verify normal internet access.
- Revoke VPN permission, test rapid stop/start, and test background/battery behavior.
- Export CSV and delete history.
- Verify that browser Secure DNS is not falsely presented as monitored.

## Architecture

`MainActivity`: native UI and consent. `DnsVpnService`: lifecycle and bounded DNS worker pool.
`DnsPacket`: bounds-checked packet codec. `TrackerRules`: domain matching.
`EventStore`: bounded local history and CSV export.
